## 1. 핵심 메시지

제조 AX의 출발점은 **“어떤 AI 모델을 쓸까?”가 아니라 “어떤 현장 문제를 어떤 데이터로 판단하게 만들 것인가?”**이다.

제조 현장에는 이미 MES, PLC, 센서, 검사장비, ERP 등에 많은 데이터가 쌓이고 있다.  
하지만 데이터가 많다고 바로 AI를 적용할 수 있는 것은 아니다.

중요한 것은 데이터를 **맥락 있게 연결하는 것**이다.

예를 들어 단순히 다음 데이터만 있다면:

```text
설비 온도 83℃
```

AI가 활용하기에는 정보가 부족하다.

반면 다음처럼 연결되면 의미가 생긴다.

```text
2026-09-10 14:32
라인2
설비 M-103
제품 A32
공정: 압착
Recipe: R17
온도: 83℃
결과: Crack 불량 발생
```

이렇게 되면 AI가 **원인과 결과의 관계**를 학습하거나 분석할 수 있다.

## 2. 제조 AX에서 필요한 데이터 6가지

| 데이터 유형 | 실제 예시 | 주요 활용 |
|---|---|---|
| 설비·센서 데이터 | 온도, 압력, 진동, 전류, RPM, 토크 | 이상탐지, 예지보전 |
| 생산·공정 데이터 | LOT, 설비, Recipe, 공정조건, 생산량 | 원인분석, 공정 최적화 |
| 품질 데이터 | 양품/불량, 불량코드, 치수, 검사값 | 불량예측, 품질 개선 |
| 이미지·영상 데이터 | 제품 이미지, X-ray, CCTV | 비전검사, 안전관리 |
| 업무·지식 데이터 | 작업표준서, FMEA, 불량보고서, 정비일지 | RAG, AI Agent |
| 사람의 판단 데이터 | 작업자 판정, 조치내용, 원인확정 | AI 성능 개선 |

특히 중요한 것은 **사람의 판단 데이터**다.

AI가 틀리거나 애매하게 판단한 사례를 사람이 수정하면,  
그 결과를 다시 학습 데이터로 활용할 수 있다.

이를 **Human-in-the-loop** 구조라고 한다.

# 3. 핵심 개념 정리

## 3.1 AX — AI Transformation

AX는 단순히 ChatGPT나 AI 검사기를 도입하는 것이 아니다.

DX가 다음과 같다면:

```text
종이 → Excel → MES → 데이터화
```

AX는 다음까지 이어진다.

```text
데이터 → 판단 → 추천 → 실행 → 학습
```

### 예시

기존 MES:

```text
어제 불량률 4.7%
```

AX 시스템:

```text
어제 라인 2의 Crack 불량이 평소보다 2.1%p 증가했습니다.

불량 발생 시점은 금형 온도가 192℃ 이상이었던 구간과
78% 중첩됩니다.

과거 동일 사례에서는 금형온도를 2℃ 낮춘 뒤
불량률이 감소했습니다.
```

즉, 단순한 **Dashboard**에서  
**Decision Support System**으로 발전하는 것이다.

---

## 3.2 RAG

RAG는 쉽게 말해:

> **회사 내부 자료를 찾아보고 대답하는 AI**

일반 LLM은 우리 공장의 과거 문제나 내부 경험을 모른다.

하지만 아래 데이터를 연결하면 달라진다.

```text
불량보고서
8D Report
FMEA
작업표준서
정비일지
고객 Claim
설비 매뉴얼
```

### 예시 질문

```text
A제품 표면 Crack이 반복되는데 과거에 비슷한 문제가 있었어?
```

AI 답변 예시:

```text
2024년 7월 동일 현상이 발생했습니다.

당시 원인은 금형 온도 상승과 냉각시간 부족이었고,
금형 온도 조정 및 냉각시간 변경 후 불량률이 감소했습니다.
```

### 실무 활용

- 신규 엔지니어 교육
- 과거 불량 사례 검색
- FMEA 조회
- 설비 고장 사례 검색
- 고객 클레임 대응
- 작업표준서 질의

---

## 3.3 AI Agent

RAG가 **찾아서 알려주는 AI**라면  
AI Agent는 다음까지 수행한다.

```text
찾기
↓
분석
↓
다른 시스템 사용
↓
결과 생성
↓
업무 실행
```

### 예시: 월간 품질보고서 Agent

기존 업무:

```text
MES 데이터 다운로드
→ Excel 정리
→ 그래프 작성
→ 원인 분석
→ 보고서 작성
```

AI Agent:

```text
MES 조회
→ 월별 불량률 계산
→ 전월 대비 비교
→ 이상 품목 탐색
→ 과거 불량 사례 검색
→ 그래프 생성
→ 품질보고서 자동 작성
```

### 실무 활용

- 품질보고서 자동화
- 생산일보 자동 작성
- 설비 이상 발생 시 정비이력 검색
- 고객 Claim 분석
- 공정 조건 추천
- 경영 KPI 보고

---

## 3.4 MLOps

제조 AI는 모델을 한 번 만들고 끝나는 프로젝트가 아니다.

현장에서는 계속 변화가 발생한다.

- 제품 변경
- 원재료 변경
- 조명 변화
- 설비 노후
- 신규 불량 발생
- 생산조건 변경

이런 변화로 인해 AI 성능이 떨어지는 것을  
**Model Drift**라고 볼 수 있다.

따라서 아래 과정이 반복되어야 한다.

```text
데이터 수집
↓
라벨링
↓
학습
↓
검증
↓
배포
↓
모니터링
↓
재학습
```

이 전체 운영 체계가 **MLOps**다.

### 실무 활용

- 비전검사 모델 자동 재학습
- 설비 이상탐지 모델 성능 모니터링
- 신규 제품 출시 시 모델 업데이트
- 다수 생산라인에 동일 모델 배포

---

## 3.5 Human-in-the-loop

AI를 100% 자동화하지 않고  
필요한 부분만 사람이 검토하는 구조다.

### 예시

```text
AI 불량 확률 99.7%
→ 자동 판정

AI 불량 확률 54%
→ 사람 검토
```

사람이 다음처럼 수정한다.

```text
Scratch 불량 맞음
```

이 데이터는 다시 좋은 학습 데이터가 된다.

구조는 다음과 같다.

```text
AI 판단
↓
애매한 사례만 사람 검토
↓
정답 수정
↓
재학습
↓
AI 성능 향상
```

# 4. 제조 AX를 실무에서 시작하는 방법

많은 기업이 다음처럼 시작한다.

```text
AI 도입
→ 데이터 수집
→ 플랫폼 구축
```

하지만 실무에서는 다음 순서가 더 효과적이다.

```text
문제
→ KPI
→ 필요한 판단
→ 필요한 데이터
→ AI
→ 업무 프로세스
```

---

## 4.1 예시: 사출공정 Crack 불량 감소

| 단계 | 질문 | 예시 |
|---|---|---|
| 문제 | 무엇을 줄일 것인가? | Crack 불량 |
| KPI | 얼마나 줄일 것인가? | 4.2% → 2.5% |
| 판단 | 무엇을 알아야 하는가? | 불량 발생 조건 |
| 데이터 | 어떤 변수가 필요한가? | 금형온도, 압력, 냉각시간, 원료 LOT |
| 분석 | 어떤 AI가 필요한가? | 불량예측 + 원인분석 |
| 실행 | 누가 결과를 사용하는가? | 생산기술 엔지니어 |
| Action | 무엇을 변경하는가? | Recipe 조정 |
| Feedback | 결과를 어떻게 저장하는가? | 조치 전후 불량률 |

핵심은 AI가 **분석만 하는 시스템**으로 끝나지 않고  
실제 공정 변경과 연결되는 것이다.

# 5. 데이터는 어떻게 연결되어야 하는가?

예시 데이터셋:

| Timestamp | LOT | Product | Machine | Process | Temperature | Pressure | Recipe | Image | Defect | Action |
|---|---|---|---|---|---:|---:|---|---|---|---|
| 14:31:02 | L24031 | A32 | M02 | Press | 187 | 32 | R12 | IMG001 | OK | - |
| 14:31:08 | L24031 | A32 | M02 | Press | 193 | 35 | R12 | IMG002 | Crack | Temp↓ |
| 14:31:14 | L24031 | A32 | M02 | Press | 194 | 35 | R12 | IMG003 | Crack | Temp↓ |

이 정도의 데이터가 쌓이면 AI에게 다음과 같은 질문을 할 수 있다.

```text
Crack 불량 발생 전 10분 동안
정상 생산 구간과 가장 차이가 큰 공정변수는 무엇인가?
```

반대로 데이터가 다음 정도만 있다면:

```text
2026-09-10
Crack
57개
```

원인 분석은 거의 불가능하다.

따라서 중요한 것은:

> **Data Quantity보다 Data Context**

이다.

## 6.1 제조지식 RAG

먼저 아래 자료를 모은다.

```text
FMEA
SOP
작업표준서
불량보고서
8D Report
정비일지
고객 Claim
설비 매뉴얼
```

AI에게 다음과 같이 질문할 수 있다.

```text
이 불량과 비슷한 사례 찾아줘.
```

```text
이 설비 고장 전에 공통적으로 발생했던 징후가 뭐야?
```

```text
이번 고객 Claim과 관련된 FMEA 항목을 찾아줘.
```

이 방식의 장점은  
숙련자의 암묵지를 조직의 지식으로 바꿀 수 있다는 것이다.

# 7. 제조 AX 발전 단계

## Level 1 — 조회

```text
어제 불량률 알려줘.
```

## Level 2 — 분석

```text
왜 불량률이 올랐어?
```

## Level 3 — 예측

```text
앞으로 어떤 LOT에서 불량 가능성이 높아?
```

## Level 4 — 추천

```text
어떤 공정조건을 조정해야 해?
```

## Level 5 — 실행

```text
허용 범위 내에서 Recipe를 수정하고
결과를 모니터링해.
```

최종적으로는  
**AI Assistant → AI Agent 기반 제조 운영**으로 발전한다.

# 8. 데이터 플랫폼보다 먼저 해야 할 것

많은 회사에서 다음과 같이 시작한다.

```text
우리도 Data Lake를 구축하자.
```

하지만 더 중요한 질문은:

> **우리 조직이 매일 반복해서 내리는 중요한 판단 10개는 무엇인가?**

이다.

### 품질팀 예시

```text
이 불량은 왜 발생했는가?
출하해도 되는가?
어느 설비가 문제인가?
이전에 같은 문제가 있었는가?
어떤 조치를 해야 하는가?
```

각 판단에 필요한 데이터를 역산한다.

이 방식이 **Use Case Driven Data Architecture**다.

# 9. 4주 제조 AX 파일럿

| 주차 | 할 일 | 산출물 |
|---|---|---|
| 1주 | 현장의 반복 문제 20개 수집 | Use Case List |
| 2주 | ROI × 데이터 준비도 평가 | 우선과제 1~2개 |
| 3주 | 필요한 데이터 연결 | 최소 데이터셋 |
| 4주 | AI / RAG / 분석 PoC | Before / After KPI |

---

## 9.1 과제 평가 기준

다음 3가지로 평가하면 된다.

```text
Business Value
×
Data Readiness
×
Implementation Difficulty
```

예시:

| 과제 | 가치 | 데이터 | 난이도 | 우선순위 |
|---|---:|---:|---:|---|
| 품질보고서 자동화 | 4 | 5 | 2 | ★★★★★ |
| 불량 원인분석 | 5 | 3 | 3 | ★★★★ |
| 예지보전 | 5 | 2 | 5 | ★★ |
| FMEA RAG | 4 | 5 | 2 | ★★★★★ |

이렇게 하면:

```text
AI로 뭐 하지?
```

라는 논의가

```text
어떤 과제를 먼저 실행할 것인가?
```

라는 구체적인 프로젝트 포트폴리오로 바뀐다.

# 10. 핵심 인사이트 3가지

## 인사이트 1. AI보다 맥락 있는 데이터가 먼저다

필요한 것은 단순한 센서 데이터가 아니다.

```text
Sensor
+
MES
+
품질
+
이미지
+
작업이력
+
사람의 판단
```

이 서로 연결되어야 한다.

---

## 인사이트 2. AI 모델보다 Feedback Loop가 중요하다

AI가 판단하고,  
사람이 교정하고,  
다시 학습하고,  
현장에 재배포하는 구조가 중요하다.

```text
AI 판단
↓
사람 검토
↓
데이터 개선
↓
재학습
↓
재배포
```

---

## 인사이트 3. AX는 데이터 프로젝트가 아니라 의사결정 개선 프로젝트다

최종 목표는:

> **데이터를 많이 모으는 공장**이 아니라  
> **데이터를 이용해 더 빠르고 정확하게 판단하는 공장**

을 만드는 것이다.

# 11. 제조 AX 전체 구조

전체 흐름은 다음과 같이 정리할 수 있다.

```text
현장
↓
데이터
↓
분석
↓
지식
↓
판단
↓
실행
↓
결과
↓
재학습
```

즉, MES, 센서 데이터, Vision AI, RAG, AI Agent, MLOps는  
각각 독립된 기술이 아니라 하나의 제조 AX 흐름으로 연결된다.

# 12. 실무 적용 체크리스트

다음 질문에 답할 수 있다면 제조 AX 프로젝트를 시작할 준비가 되어 있는 것이다.

- 우리가 해결하려는 현장 문제는 무엇인가?
- 현재 KPI는 얼마이며 목표 KPI는 얼마인가?
- 그 문제를 해결하려면 어떤 판단이 필요한가?
- 그 판단에 필요한 데이터는 무엇인가?
- 데이터는 설비, LOT, 제품, 공정 기준으로 연결되어 있는가?
- 품질 결과와 공정 조건을 함께 볼 수 있는가?
- 과거 조치 이력이 남아 있는가?
- 사람의 판단과 수정 결과가 저장되는가?
- AI 결과를 실제 업무 프로세스에 연결할 수 있는가?
- AI 적용 전후 성과를 비교할 수 있는가?
